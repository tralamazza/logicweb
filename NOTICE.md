## Why GPL, and why it is not a constraint imposed from outside

An earlier version of this file flagged the copyleft question as open: the app bundles
GPL'd decoders, and that limits how the combined work may be distributed. GPLv3 answers
it. Bundling GPL decoders into a GPL application is what the licence is for.

The compatibility this depends on was checked rather than assumed. Across all 132
decoders in `public/decoders/decoders.zip`, as self-declared in each decoder's metadata
and confirmed against the licence header in each source file:

| Declared licence | Decoders |
|---|---|
| GPLv2-or-later | 117 |
| GPLv3-or-later | 8 |
| MIT | 4 |
| BSD | 2 |

277 "at your option, any later version" clauses, and **no GPLv2-only file anywhere** -
every file that says "version 2" also grants the later-version option. That is the load
bearing fact: GPLv2-only material would have been *incompatible* with GPLv3 and would
have forced this project to GPLv2 instead. It upgrades cleanly.

## libsigrokdecode protocol decoders

`public/decoders/decoders.zip` holds the stock protocol decoders from libsigrokdecode
(the sigrok project), licensed as tabulated above. The zip is not committed - it is staged
into `public/` by `npm run vendor` - but it is shipped in `dist/`, so the licences travel
with any deployment.

`src/decode/decoders/manifest.ts` **is** committed, and it is not original work. It is
generated by `src/decode/tools/build-manifest.py` from those decoder sources and contains,
for all 131 decoders, their long names, descriptions, option and channel names, and every
annotation and annotation-row description. That is roughly 180 KB of text authored by the
sigrok project. Whether interface metadata of this kind is separately copyrightable is
arguable and this repository does not rely on the answer: the file carries the same
GPL-3.0-or-later notice as everything else, emitted by the generator so that re-vendoring
reproduces it.

Source: https://sigrok.org/wiki/Libsigrokdecode

## Pyodide

`public/pyodide/` is the Pyodide distribution - CPython and its standard library compiled
to WebAssembly - used to run the decoders in the browser. Pyodide is licensed under the
**Mozilla Public License 2.0**, which is GPL-compatible through MPL 2.0's secondary
licence provision. It embeds CPython, under the **Python Software Foundation License**,
which is permissive and GPL-compatible.

Pyodide is likewise vendored rather than committed.

**Known gap:** `npm run vendor` copies the seven runtime files Pyodide actually loads and
does not copy Pyodide's own licence files, so a deployed `dist/` currently redistributes
MPL-2.0 and PSF code without shipping their notices. This does not affect the repository,
where nothing of Pyodide is committed, but it should be fixed in `vendor-assets.mjs`
before treating a deployment as licence-clean.

## Everything else

All remaining code in this repository is original work, with `manifest.ts` as the single
stated exception above. It contains no third-party sample data, screenshots, or
proprietary file-format material. The captures in `fixtures/` were recorded on the
author's own hardware.

## What GPLv3 does and does not require of a deployment

GPLv3 obligations attach to *conveying* the program. Serving the JavaScript bundle, the
WebAssembly and the decoder zip to a browser is generally treated as conveying, so the
people loading the site are recipients who are owed corresponding source. A public
repository containing this source satisfies that.

GPLv3 is not AGPLv3: it imposes nothing extra merely because the software is reachable
over a network.
